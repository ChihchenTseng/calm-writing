## 一、專案背景與研究動機

現代人面臨高壓生活環境，情緒調節需求日益迫切。傳統書法練習在東亞文化中長期被視為具備靜心效果，然而其背後的生理與心理機制尚未被數位化與量測。

《寫字靜心》旨在將傳統書法與現代生物特徵擷取技術結合，透過分析使用者書寫行為模式，即時評估其壓力水平並提供個人化的情緒調節引導。系統同時兼顧研究嚴謹性與商業可行性，特別聚焦於客語書法練習，服務中高齡族群的健康促進需求。

**研究問題：**
書寫的生物特徵（筆壓、速度、停頓、震顫等）是否能作為壓力狀態的有效指標？若能，其特徵擷取管線如何在消費級硬體上實現？

## 三、系統功能與架構

### 3.1 使用流程

1. **歡迎頁** — 顯示夥伴人數、進入選項
2. **選題頁** — 選擇書寫任務（預設客語俗諺、自訂內容），記錄書寫前情緒（Pre-mood）
3. **書寫頁** — 即時擷取手寫生物特徵，依需要觸發呼吸引導
4. **結果頁** — 顯示壓力等級卡片、書寫成就徽章卡、特徵摘要

### 3.2 技術架構

**前端**
單一 HTML 檔案（無框架依賴），包含：
- Canvas API 手寫繪圖層（支援橡皮擦、筆跡疊層）
- Pointer Events API（讀取真實壓力 `e.pressure`、傾斜角度 `e.tiltX/tiltY`）
- CSS scale-based 螢幕縮放時 `getPos()` 座標修正
- 花蓮明朝字體（HanaMinA/B）via jsDelivr CDN，支援客語特殊字型

**後端（雙軌架構）**

目前採用 Google Sheets 與 Firebase 雙後端並行，各自服務不同目的：

*Google Sheets（研發者研究用資料確認）*
透過 Google Apps Script `doGet` + `?data=encodeURIComponent(JSON)` 架構接收資料，以 GET 請求規避 `no-cors` CORS 限制。定位為**研發人員的資料確認工具**，每次書寫完成後，26 欄完整的生物特徵與壓力評估結果會即時寫入試算表，研發人員可直接在 Google Sheets 介面逐筆檢視每筆資料是否正確（如筆壓是否有效、壓力等級是否合理估算、null 欄位是否如預期），並可隨時匯出來統計分析或使用。Google Sheets 不對終端使用者開放，純粹作為後端資料監控與學術研究的資料來源。

*Firebase Realtime Database（使用者端視覺化與社群互動）*
專案名稱：`calm-writing`，採匿名登入（Anonymous Auth），以 `uid` 作為使用者識別。定位為**使用者看得到的功能後端**，負責支撐兩大類體驗：(1) 個人練習成效顯示——使用者可在成就頁面看到自己的歷史書寫紀錄、連續天數、成就徽章、每週心情日曆等；(2) 社群互動功能——包含夥伴牆（顯示目前多少人同時在線上書寫）、心情泡泡牆（書寫完成後匿名投放心情字詞與其他人共享）。所有需要跨 session 保存或即時多人同步的功能皆由 Firebase 承接，詳見 3.4 節。

**部署**
- GitHub Pages（`ChihchenTseng/calm-writing`）
- GitHub Actions 自動部署（`deploy-v.yml` 產品版、`deploy-t.yml` 研究版）

**相容硬體**
- iPad + Apple Pencil（主要研究設備）
- HUION H430P / RTE-100-K 繪圖板（經由 Windows Ink 模式）

### 3.3 Google Sheets 資料本位（26 欄）

| 欄位群組 | 欄位名稱 |
|----------|----------|
| 基本資訊 | timestamp, user_id, session_id, task_text |
| 情緒記錄 | pre_mood, post_mood |
| 書寫行為 | session_duration_sec, stroke_count, char_count |
| 生物特徵 | avg_pressure, pressure_cv, avg_speed, avg_pause_duration_ms, pause_count |
| 壓力評估 | stress_level, stress_index, stress_dominant_feat |
| 系統輸出 | breathing_triggered, emotion_result（保留欄，目前 null） |

### 3.4 Firebase Realtime Database 結構

Firebase 是使用者直接感受到的功能後端，服務個人成效視覺化（成就頁面、徽章、心情日曆）與社群互動（夥伴牆、心情泡泡）。以下為目前已實作的資料節點，以及為完成既有功能需要新增的節點。

**已實作節點**

| 路徑 | 內容 | 對應功能 |
|------|------|----------|
| `presence/{uid}` | `{ ts: ServerTimestamp }` | 夥伴牆（統計目前線上人數）斷線自動刪除 |
| `daily/{YYYY-MM-DD}/count` | 整數 | 今日書寫人次計數器 |
| `daily/{YYYY-MM-DD}/moods/{pushId}` | `{ mood, ts }` | 心情泡泡牆（每次書寫後投放的匿名心情字詞） |
| `users/{uid}/sessions/{pushId}` | `{ date, text, mood, emotion, totalTime, strokeCount, ts, clientTs, streak, total_sessions }` | 書寫紀錄，依成就頁面顯示歷史 |
| `users/{uid}/stats` | `{ streak, lastDate, totalSessions, badges, calmCount }` | 連續天數、累計次數、成就徽章 |
| `users/{uid}/repEmotions/{YYYY-MM-DD}` | `{ emotion, clientTs }` | 每天的代表心情，用於週曆或月曆顯示 |

**為完成既有功能需新增或補強的節點**

*書寫生物特徵摘要（依成就頁面歷史紀錄使用）*
目前 `users/{uid}/sessions` 子節點僅有情緒欄位，不含生物特徵數值。若未來成就頁面要顯示「每次書寫的壓力趨勢」時間軸視覺化表，需在每筆 session 中新增特徵摘要：
```
users/{uid}/sessions/{pushId}/features: {
  avg_pressure, pressure_cv,
  avg_pause_duration_ms, pause_count,
  stroke_count, writing_speed,
  stress_level, stress_index, stress_dominant_feat,
  avg_tilt_mag, baseline_variance
}
```

*書寫軌跡原始點（依回放視覺化歷史需求）*
目前 `rawPoints` 僅存在 `sessionData`（記憶體）與 `localStorage`，書寫結束後刷新頁面即遺失，且無法跨裝置存取。若要讓歷史書寫也能回放動畫，需將一定取樣後的 rawPoints 存入 Firebase（建議最多保留 500 點以控制資料量）：
```
users/{uid}/sessions/{pushId}/rawPoints: [
  { x, y, pressure, tiltX, tiltY, tiltMag, charId, strokeId, ts }, …
]
```
注意：rawPoints 資料量較大，需評估 Firebase 免費方案的每日下載量限制（目前免費額度為 10 GB/月），若使用者數增加或擴大保存特徵摘要而非完整點位資料。

*每日書寫統計總覽（依未來分析儀表板使用）*
若要呈現群體層級的書寫趨勢（如每日平均壓力、參與人數分布），可在 daily 節點下增加總覽欄位：
```
daily/{YYYY-MM-DD}/summary: {
  total_sessions, avg_stress_level, mood_distribution
}
```
此節點目前不存在，需在 Apps Script 或後端寫入邏輯中一併建立。

## 四、StressEngine v2 壓力推估引擎

### 設計原理

採用 **加權投票機制**，以 N=57 參考組的實際資料的 P25/P75 分位數作為高低壓力閾值。

| 特徵 | 權重 | 心理意義 |
|------|------|----------|
| avg_pressure（平均筆壓） | 2.0 | 肌肉緊繃程度的直接指標 |
| session_duration_sec（書寫時長） | 1.5 | 任務投入度與專注循環週行為 |
| avg_pause_duration_ms（平均停頓時長） | 1.5 | 認知負荷與猶豫程度 |
| pause_count（停頓次數） | 1.0 | 書寫流暢度 |

**排除欄位：** `avg_char_spacing`（字間距演算法產生負值，資料品質不可靠）

### 效能指標（N=57 驗證組）

- 精確準確率：47.4%
- 相鄰準確率：89.5%（允許 ±1 等級誤差）

### 呼吸引導觸發條件

當筆壓異常偏高（壓力閾值觸發機制，V14 起）：
- 真實觸控筆（`pointerType === 'pen'`，或觸控但偵測到非預設壓力值）壓力 ≥ 45% 時觸發呼吸引導
- 觸發後以 `breathingTriggered` 旗標鎖定，避免同一次壓力高峰重複觸發
- 解除鎖定條件（兩者擇一滿足即可，互不抵觸）：
  - 壓力降至 35% 以下（`pressurePercent < 35`）→ 立即解除
  - 呼吸引導結束後 20 秒冷卻期屆滿（`breathingCooldownUntil`）→ 冷卻期內即使壓力再次 ≥45% 也不會重新觸發

> 速度雙層判斷（3 秒滑動窗平均速度 ≥ 180 pts/sec、持續 2 秒）為過去曾規劃但未實作的備案方案，目前未採用，僅記錄於此供未來若壓力判斷失準時參考評估，非現行設計。

## 五、統計研究方法

### 5.1 分析管線

1. **Shapiro-Wilk 常態性檢定** — 確認資料分佈，決定後續統計方法
2. **Spearman 相關分析** — 特徵與壓力量表的相關性（通常常態確認後使用）
3. **Benjamini-Hochberg FDR 校正** — 多重比較誤差控制
4. **VIF 共線性診斷 + 多元線性迴歸** — 特徵重要性排序
5. **5-fold 交叉驗證** — 模型泛化能力評估

### 5.2 測量工具

| 工具 | 測量對象 | 說明 |
|------|----------|------|
| VAS（Visual Analogue Scale） | 主觀壓力 | 即時心理自評 |
| PSS-10（Perceived Stress Scale） | 認知壓力 | 測量個人的認知評變 |
| ISS / DeLone & McLean 2003 | 系統品質 | 資訊系統成功模型 |
| Fogg Behavior Model | 動機設計 | 系統仿修設計依據 |

**重要區分：** PSS-10 測量使用者心理的認知變化，ISS 評估系統本身的品質表現。兩者在論文中必須明確分開討論。

### 5.3 已確認統計結果（N=57）

- VAS × PSS-10 收斂效度：r = .365，p = .007（顯著）
- `avg_pressure` 與 VAS 壓力，趨勢正相關
- `session_duration_sec` 群組差異：Kruskal-Wallis p = .026（顯著）
- `avg_char_spacing`（因負值問題）**全數排除**

## 八、專案定位敘述

《寫字靜心》是一個結合傳統書法與現代生物特徵分析的數位健康工具，透過捕捉使用者的書寫行為模式，即時評估壓力狀態並提供情緒調節引導。

學術面向，本專案致力於建立完整的線上書寫特徵擷取管線，並以實徵資料提供初步方向性證據。研究貢獻定位為可行的測量管線與初步相關性發現，而非已驗證的壓力預測模型。學術寫作採正式繁體中文，引用格式遵循 MIS Quarterly，統計報告需區分測量誤差、信賴區間與 FDR 校正後的 p 值。

產品面向，本專案以中高齡族群健康促進為核心提案定位，結合客語書法元素，透過 B2B2C 模式推動數位健康工具的實際落地應用。

## 九、設計目標落差與待解決問題

本節記錄設計規格與目前實作（V13）之間的落差，以及已知需要修正的問題，作為後續版本迭代的依據。

### 9.1 功能尚未實作

**書寫結果視覺化（研究版）**
Python 版本（`handwriting-features-test8.py`）已驗證以下四種呈現輸出，尚未整合至 App 的書寫結果頁面：
1. 手寫軌跡動畫回放（每個字以不同顏色繪出筆跡路徑）
2. 筆壓時序趨勢折線圖（書寫全程壓力變化，含平均線）
3. 握筆姿勢 3D 動作圖（TiltX / TiltY / 筆壓三維散點，隱藏無傾斜感應硬體的 fallback）
4. 逐字書寫特徵卡片（特徵數值自動轉成白話描述，不顯示原始數字）

Python 版本中已計算但 App 尚未追蹤的欄位（字間距、行距相對前一個 dy）、跨階段行為在現行 `sessionData.rawPoints` 結構中可以計算，但未回報至 Google Sheets。

**`pressure_cv` 尚未納入 StressEngine 評估**
`pressure_cv`（壓力係數變異）已上載至 Google Sheets，但 StressEngine v2 的加權投票目前仍使用 `avg_pressure`（原始均值）作為主要特徵。設計規格指出 pressure_cv 相較於壓力均值更具診斷意義（反映壓力衰減軌跡），尚未將其正式納入並重新校正權重與閾值。

**Firebase 與 Google Sheets 欄位對應尚未完整**
兩套後端定位不同（Sheets 供研發人員確認資料、Firebase 供使用者端功能），各自存放不同欄位，且須維持一份資料的雙軌。目前落差為：Google Sheets 有完整 26 欄的生物特徵，但 Firebase sessions 節點僅存行為與情緒欄位，不含生物特徵數值。這使得使用者端的歷史回顧缺少壓力數據支撐。需決定：(1) Firebase sessions 是否要補上生物特徵摘要（`features` 子節點），以支援使用者在成就頁面的歷史壓力趨勢視覺化；(2) 寫入邏輯如何確保一致，目前 Sheets 與 Firebase 為兩次獨立呼叫寫入請求，若其中一端失敗無重試機制，可能導致兩端資料不同步。

### 9.2 演算法問題

**`avg_char_spacing` 負值問題（尚未修正，暫時排除）**
字間距計算公式為 `curr.minX - prev.maxX`，當相鄰水平重疊時（特別是書寫連筆字或字形較寬時），`minX` 會小於 `prev.maxX`，導致產生負值。目前僅以 `gap > -50` 做部分過濾，但根本問題在於字元分割（`segmentChars()`）的 X 軸中心點最近派邏輯，無法處理連筆跨越相鄰字格的情況。此欄位已在數據排除分析，待演算法修正後恢復。

**字元分割準確度不足**
`segmentChars()` 以筆劃 X 軸重心與字格中心的距離最短作為分派依據，在多字書寫時可能出現誤判（單一字的筆劃被分到相鄰字，尤其字形較大、筆劃橫跨多格時尤其明顯，影響逐字特徵計算的準確性。

**`emotion_result` 分類為規則式硬編算法，非資料訓練**
`analyzeWriting()` 中的 calm / focused / tense 分類採用硬編碼閾值（如 `pressureVariance > 0.25` 則 tenseScore += 0.4），邏輯並非從資料中學習而來，與 `selectedMood` 的主觀情緒直接寫入客觀特徵分數中，可能造成循環論證。目前定位為試探性分類規則，論文中需明確說明此限制。

### 9.3 已解決的歷史問題（供參）

| 問題 | 解決方式 | 版本 |
|------|----------|------|
| Google Sheets CORS 錯誤 | 改用 GET + URL 編碼 JSON，禁用 POST no-cors | V10 前 |
| Canvas undo 座標偏移 | `save/restore` 繞過 DPR scale transform | V10 前 |
| 呼吸引導觸發條件與設計規格不符（原記錄為速度雙層判斷 vs. 實作為壓力閾值觸發，且缺冷卻機制） | 經 PM 確認：維持壓力閾值觸發（`avg_pressure` 與 VAS 壓力呈正相關趨勢，暫無證據顯示壓力判斷失準），僅補上遺漏的 20 秒冷卻機制（`breathingCooldownUntil`），並同步修正本文件與 CLAUDE.md 之設計敘述，消除規格與實作落差。速度雙層判斷（3 秒滑動窗、180 pts/sec）保留為未來備案，若後續資料顯示壓力判斷失準再評估導入 | V14 |
| Hakka 字型無法渲染 | 改載入花蓮明朝字型（jsDelivr CDN） | V7 |
| 壓力結果回傳為 null | 修正 `const` hoisting bug | V10 |

現有 Python 原型程式已驗證以下四種呈現輸出，未來需整合至 App 的書寫結果頁面，以使用者容易理解的方式呈現：

1. **手寫軌跡動畫回放**：將書寫路徑重新繪於獨立面板，每個字以不同顏色呈現，讓使用者能看到自己書寫的軌跡與節奏
2. **筆壓時序趨勢折線圖**：以折線圖呈現書寫全程的壓力體感變化（隨時間），標示平均筆壓線，方便查看整段書寫節奏是否穩定
3. **握筆姿勢 3D 動作圖**：以三維散點圖呈現 TiltX（水平傾角）、TiltY（垂直傾角）、筆壓的空間分佈（顏色深淺對應壓力強度），隱藏無傾斜感應硬體的 fallback 顯示
4. **逐字書寫特徵卡片**：每個書寫字元一張卡片，自動將特徵數值轉成白話描述，如：「筆壓：輕柔（適中）偏低」、「按壓：幾乎沒有」「微微握著」、「大小：適中（適中）」「豪邁」、「底線：工整（自由奔放）」，不直接顯示原始數值

Python 原型中計算的特徵欄位包含：底線角度（arctan2 計算）、字體大小（bounding box 面積）、行距與字距（相對前一點 dx/dy）、下滑距（y 座標）、筆壓（0–1023 映射）、傾斜角度（tiltX² + tiltY² 平方根）。
